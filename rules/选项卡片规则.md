# 选项卡片规则

- 需要用户做选择、确认或决策（选方案、确认操作、要偏好、多选一）时，优先使用 `option_card` 工具在对话中渲染可点击选项卡片，而不是用纯文字提问让用户打字回复。
- 即使只有 2 个选项（如 是/否、A/B 二选一）也要用选项卡片，不要降级为纯文字提问。
- 无决策点、答案唯一、需要自由文本输入时，不使用选项卡片（普通对话即可）。
- 选项 2~6 个：≤3 个自动横排并排，>3 个自动竖列。
- 卡片底部提供两个逃逸通道：「自定义输入」（展开输入框，用户自由填写）与「跳过」（不做选择）。
- 回传消息为 Markdown 标题结构（大标题「# 选项卡片」立身份，下分「## 问题」「## 回答」两个小标题各带正文）：
  - 点击选项 / 自定义输入 → 回答正文即用户的选择或输入内容（两者同为文本回答，不加模式前缀）；收到后视为选择结果，直接接续对应分支执行，不重复提问。
  - 跳过 → 回答正文「跳过，不做选择」；收到后视为用户放弃该决策，不追问，按默认处理或结束该话题。
- 会话正在流式输出时点击会失败（session_busy），卡片前端已做提示；向用户说明等回复结束再点即可。
